# 行为树节点示例

## RouteNode 模式：长时间运行的计划消费者

适合可能持续多帧运行的节点：

- 导航
- 种地循环
- 清理障碍
- 浇水
- 回家睡觉

关键特征：

- 从 `blackboard.macro_plan` 读取当前任务。
- 当前任务类型不匹配时，返回 `"FAILURE"`。
- 维护本地状态，例如开始时间、缓存路径、路线索引、`is_doing`。
- 每帧使用 `context.state`。
- 发送确定性的执行器命令。
- 从游戏状态验证成功。
- 完成验证后推进 `blackboard.current_step_index`。
- 返回最终 `"SUCCESS"` 或 `"FAILURE"` 前重置本地状态。

当节点拥有一个多帧宏观目标时，使用这种模式。

## OpenDoorNode 模式：短交互闸门

适合处理小型跨节点交互：

- 开门
- 关闭对话框
- 确认弹窗
- 按一次或少量几次交互键

关键特征：

- 通常由黑板标志控制，例如 `require_open_door`。
- 如果动作不需要执行，快速返回 `"SUCCESS"`。
- 只发送少量命令。
- 把已知游戏反馈转成规划器恢复状态。
- 除非这个动作本身就是宏观任务，否则不消费无关计划步骤。

当节点是 `Sequence` 内部的辅助闸门时，使用这种模式。

## Defend_Node 模式：高优先级保护节点

适合安全检查：

- 血量低
- 附近有怪
- 体力过低
- 玩家卡在危险状态

关键特征：

- 放在顶层 `Selector` 的靠前位置。
- 不需要防御时返回 `"FAILURE"`，让正常任务继续。
- 正在防御或逃跑时返回 `"RUNNING"`。
- 只有当前帧应被视为已处理时才返回 `"SUCCESS"`。

当节点用于打断正常行为或处理紧急情况时，使用这种模式。

## LLM_Node 模式：后台规划器兜底

只适合高层规划：

- 解析原始自然语言任务。
- 商店打烊、路线堵塞、资源不足后的重新规划。
- 给确定性节点生成宏观任务。

关键特征：

- 启动异步规划器工作，不阻塞帧循环。
- 使用 `blackboard.is_llm_thinking` 和 `blackboard.new_plan_received`。
- 写入新的 `blackboard.macro_plan`。
- 规划中返回 `"RUNNING"`。
- 新计划到达后返回 `"FAILURE"`，让顶层 `Selector` 从高优先级分支重新扫描。

不要把这个模式复制到低层移动或交互节点里。

## 如何选择模式

节点要完成一个宏观任务时，使用长时间运行的计划消费者模式。

节点只是为了帮助另一个宏观任务解锁某个交互时，使用短交互闸门模式。

节点要打断正常行为处理风险时，使用保护节点模式。

只有确定性节点无法决定下一步宏观计划时，才使用规划器兜底模式。
