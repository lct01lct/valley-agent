# C# 与 SMAPI 编码规范

## 命名与结构

- 类型、公开方法和属性使用 `PascalCase`；局部变量和参数使用 `camelCase`；私有字段使用 `_camelCase`。
- 可变依赖通过构造函数传入，能够只读的字段标记为 `readonly`。
- 每个方法保持单一职责：网络接收、JSON 解析、游戏动作和响应发送分别处理。
- 新增代码遵循现有项目目标框架和 C# 语言版本，不擅自引入无法由当前 SMAPI 环境加载的语法或依赖。

## SMAPI 与线程

- 通过 SMAPI 事件和输入 API 操作游戏，不从 TCP 后台线程直接执行不安全的游戏状态修改。
- 网络线程负责收包、解析和投递意图；需要主线程确认的结果通过共享状态或事件循环处理。
- 共享状态必须有清晰的线程所有权；确需跨线程读写时使用锁或线程安全结构。
- `UpdateTicked` 中的工作保持轻量，不执行阻塞网络读取、长时间等待或模型调用。
- 正确清理 `TcpListener`、`TcpClient`、`NetworkStream` 和事件相关资源。

## 协议与序列化

- 优先使用结构化对象和 JSON 序列化器生成载荷，不手工拼接复杂 JSON。
- JSON 字段名属于跨语言协议契约。C# 输出为 `Stone`、`PlayerHealth` 等 `PascalCase` 字段时，Python 必须按相同大小写读取；不要要求接收端猜测或自动转换字段名。
- 已建立的字段名保持稳定。确需指定线上的名称时，使用明确的序列化标注，例如 `[JsonProperty("Stone")]`，并同步更新 Python 解析模型和协议测试。
- 项目中的既有协议同时存在 `snake_case` 字段。修改时以实际线上字段为准，不要仅为统一命名批量改变协议。
- 每条 TCP 消息使用明确帧边界；当前命令与响应以换行分隔，状态快照以约定结束标记分帧。
- 每个受支持动作都返回结构化或明确的成功、失败、超时结果；未知动作不能伪装成执行成功。

## 异常与日志

- 捕获具体异常并通过 `_monitor.Log(...)` 记录组件、操作和异常消息。
- 不新增空的 `catch { }`。清理阶段若必须忽略异常，应限制作用域并注释原因。
- 客户端断开属于可恢复事件；监听端口失败、协议损坏和游戏 API 失败需要区分日志级别。
- 面向开发者的日志使用简洁中文，协议值和动作名保持稳定英文。

## 状态导出

- Observer 输出字段应稳定、可空性明确，并避免每帧重复计算不变数据。
- 新增直接来源于 SMAPI／Stardew Valley API 的 state 字段时，尽可能沿用原生成员名及大小写。例如实际读取 `player.Stamina` 时，传输字段优先命名为 `Stamina`；不要无必要改成 `stamina`、`player_stamina` 或其他自定义变体。
- 在编码前从当前项目引用的 SMAPI／游戏程序集确认原生成员名，不凭记忆猜测名称。
- 如果字段是多个原生值计算、聚合或归一化后的结果，不冒充某个原生属性；使用清晰稳定的派生字段名，并在代码中说明来源或计算语义。
- 既有 state 字段即使没有遵守原生命名，也不能直接批量重命名。需要迁移时同步修改 Python 消费端、测试和协议版本，必要时保留兼容别名。
- 地图切换时刷新场景缓存；动态状态按需要更新。
- 扩展游戏快照时，同时更新 Python 解析模型和对应验证，避免只改一侧。
