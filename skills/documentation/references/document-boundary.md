# 文档边界参考

## README.md

定位：项目门面。

适合写：

- 项目目标和一句话定位。
- 总体架构方向，例如“行为树 + AI 决策 + SMAPI 结构化状态”。
- 当前阶段的高层摘要。
- 系统架构图和少量解释。
- 目录结构、环境启动、文档导航。
- 当前能力的高层列表，不展开实现流程。

不适合写：

- 具体节点内部流程。
- 工具动作等待机制。
- Chest / Inventory / 菜单协议细节。
- SMAPI JSON 请求和响应样例。
- 黑板字段、重试次数、超时参数。
- 频繁变化的 P0/P1/P2 任务细则。

## AGENTS.md

定位：Agent 开发契约。

适合写：

- Codex 修改项目之前必须知道的事实源。
- 行为树运行契约和节点边界。
- State、Blackboard、Context、Executor 的职责边界。
- 工具动作、持续移动、交互站位、结构化动作等实现约束。
- C# / Python 协议命名规则。
- 必须读取哪些项目 skills。
- 安全改动、验证和 Git 工作区要求。

不适合写：

- 每日进度流水账。
- 太长的未来规划列表。
- 只对某个阶段暂时有效的验收细节。

## docs/current-stage.md

定位：当前阶段事实板。

适合写：

- 当前 P0/P1/P2 阶段的目标、完成情况和验收标准。
- 当前已知缺口、风险、真实游戏表现和近期修复方向。
- 当前 mock 数据和测试任务说明。

不适合写：

- 长期稳定开发契约。
- 项目首次介绍。

## docs/next-development-plan.md

定位：后续开发路线。

适合写：

- 未来模块设计草案。
- 暂不实现但需要保留的计划。
- 开发优先级、依赖关系和验收草案。

不适合写：

- 当前源码已经必须遵守的硬规则。
- README 级别的项目介绍。

## 判断口诀

- 新人第一次打开项目需要知道吗？放 README。
- Agent 改代码必须遵守吗？放 AGENTS。
- 只描述当前阶段状态吗？放 current-stage。
- 是未来想做但还没做吗？放 next-development-plan。
- 是某个专题设计，且会越来越长吗？新建 docs 专题文档。
